# needteacher MVP 명세 (v2)

- 근거: `docs/research/market.md`(T-041), `docs/research/regulation.md`(T-042), 리뷰 T-043(Codex)·T-044(agy).
- 사용자 결정 (2026-10-15):
  - 선생님 프로필만 게시, 앱 내 채팅, 대학 이메일 확인, 학부모·선생님만 가입.
  - 로그인은 이메일 코드와 카카오 둘 다, 알림은 이메일.
  - 프론트엔드는 Vite + React + TS.
  - MVP에 넣을 것: 고교 필터, 찜하기, 첫 문의 템플릿.

## 한 줄 정의

수성구 학부모가 동·과목·학년·출신 고교로 선생님 프로필을 찾아 앱 안에서 대화를 시작한다. 전단지 한 장이 하던 일(누가, 무엇을, 어디서, 얼마에)을 교습비·신고 정보와 대학 이메일 확인 배지를 갖춘 프로필로 바꾼다.

## 사용자와 권한

| 사용자 | 할 수 있는 일 |
|---|---|
| 비로그인 방문자 | 검색, 프로필 상세 열람. 문의·찜을 누르면 로그인으로 보낸다 |
| 학부모 | 위 + 채팅 시작, 찜하기, 차단·신고 |
| 선생님 | 프로필 작성·수정·공개/숨김, 대학 이메일 확인, 채팅 응답, 차단·신고 |
| 학생 | 가입하지 않는다 (14세 미만 법정대리인 동의 절차를 피함, regulation §2) |

- 한 계정은 한 역할이다. 역할은 바꿀 수 없다.
- 미인증 요청은 `401`, 역할·소유자가 다르면 `403`.
- 가입 시 "만 14세 이상입니다" 본인 확인 체크를 받는다. 이 체크는 자기 진술일 뿐, 나이나 법정대리인 권한을 검증했다고 표현하지 않는다.

## 기능

### F1. 로그인

- **F1a 이메일 코드:**
  - 이메일 주소로 6자리 코드를 보내고, 맞으면 로그인한다. 처음이면 역할을 고르고 가입한다. 비밀번호는 없다.
  - 코드는 10분 동안 유효하다. 5회 틀리면 그 코드는 무효가 된다. 재전송은 1분에 한 번이다.
- **F1b 카카오:**
  - 카카오 계정으로 로그인한다.
  - 카카오에서 이메일을 받지 못하면 F1a 방식으로 이메일을 확인받는다. 알림 받을 주소가 필요하기 때문이다.
- 같은 이메일은 한 계정에만 연결된다.
- 탈퇴는 F7.

### F2. 선생님 프로필

| 항목 | 필수 | 규칙 |
|---|---|---|
| 표시 이름 | O | 1~20자 |
| 과목 | O | 코드 목록에서 1~5개 |
| 대상 학년 | O | 코드 목록에서 1개 이상 |
| 수업 가능 동 | O | 수성구 행정동 23개 중 1개 이상 |
| 교습비 | O | 아래 "교습비" 참고 |
| 신고 유형 | O | `REPORTED`(신고번호 필수) 또는 `ENROLLED_EXEMPT`(대학 재학 중 면제, 신고번호 없음) |
| 대학·학과 | O | 자기 기재 |
| 출신 고교 | | 고교 코드 목록에서 1개. 자기 기재라 배지 없음 |
| 소개 | | 최대 1000자 |

- **교습비:**
  - 프로필당 하나다 (과목별 가격 없음).
  - `amountWon`(1원 이상)과 `unit`을 받는다.
  - `unit`이 `PER_SESSION`이면 `sessionMinutes`가 필수다. `PER_MONTH`이면 `sessionMinutes`와 `sessionsPerMonth`가 필수다.
  - "협의"만으로는 저장할 수 없다 (학원법 제15조 광고 표시, regulation §1).
- **공개 상태:**
  - 처음 만들면 `HIDDEN`(임시 저장)이다. 작성자가 `PUBLIC`으로 바꾸면 검색에 나온다.
  - 숨기면 목록과 상세에서 즉시 빠진다.
  - 선생님 한 명은 프로필 하나만 가진다. 두 번째 생성은 `409`.
- 연락처 칸은 없다. 연락은 채팅으로만 한다.
- **공개 표시 (목록 카드와 상세 동일):**
  - 이름, 과목, 학년, 동, 교습비와 기준, 대학·학과, 출신 고교, 배지.
  - 신고 정보는 `REPORTED`면 "개인과외교습자 신고번호 ○○○ (본인 기재)"로, `ENROLLED_EXEMPT`면 "대학 재학 중 신고 면제 (본인 기재, 미검증)"로 표시한다.
  - "교육청 인증"이라는 표현은 쓰지 않는다.
- 공개 응답에 넣지 않는 것: 작성자 계정 ID, 로그인 이메일, 확인한 대학 이메일.

### F3. 대학 이메일 확인

- 선생님이 정확히 `.ac.kr`로 끝나는 주소를 입력하면 코드를 보낸다. 코드 규칙은 F1a와 같고, 발송 기능도 같은 것을 쓴다.
- 확인되면 배지는 **"대학 이메일 확인"**이다. 이 배지는 그 주소로 메일을 받을 수 있다는 뜻일 뿐이다. 재학·학과·신고 여부를 증명하지 않으며, 그렇게 보이는 문구도 쓰지 않는다.
- 졸업생 등 확인하지 않은 선생님도 바로 검색에 나온다. 배지만 없다.
- 대학 이메일을 바꾸거나 탈퇴하면 배지를 회수한다. 확인한 주소는 공개하지 않는다.

### F4. 검색

- 비로그인도 쓸 수 있다.
- **필터:** 동·과목·학년·출신 고교. 모두 선택 사항이다.
  - 같은 필터 안의 여러 값은 OR, 서로 다른 필터는 AND로 묶는다.
  - 필터가 없으면 공개 프로필 전체가 나온다.
- **정렬과 페이지:**
  - `updatedAt` 최신순으로 정렬하고, 시각이 같으면 `id` 역순이다.
  - 커서 기반 페이지다. `limit`의 기본값은 20, 최대 50이다.
- **오류:**
  - 잘못된 코드·`limit`·커서는 `400`이다. 결과가 없으면 빈 목록을 돌려준다.
  - 없는 프로필과 숨긴 프로필의 상세 조회는 둘 다 `404`다. 존재 여부를 드러내지 않기 위해서다.
- 위치 측위(GPS)는 쓰지 않는다 (regulation §4).

### F5. 채팅

- **대화방:**
  - 학부모만 대화를 시작할 수 있고, 대상은 공개 프로필이다.
  - 학부모-선생님 쌍마다 방은 하나다. 다시 시작하면 기존 방을 돌려준다.
- **메시지:**
  - 텍스트만 1~1000자다. 사진·파일은 없다.
  - 목록은 커서로 받고, 새 메시지는 폴링으로 확인한다 (WebSocket은 나중에).
- **첫 문의 템플릿:** 학년, 희망 요일·시간, 고민을 칩으로 골라 첫 메시지를 채운다. 프론트엔드에서만 처리하고, API는 일반 메시지와 같다.
- **입력 안내:** 입력창에 "학생 실명·학교·주소는 적지 마세요"라고 안내한다. 연락처는 당사자가 직접 주고받는다. 플랫폼이 연락처를 대신 넘기지 않는다.
- **이메일 알림:**
  - 받는 사람이 그 방을 마지막으로 읽은 뒤 처음 온 메시지에 한 번만 보낸다. 이후 메시지는 다시 읽을 때까지 보내지 않는다.
  - 메일에는 본문을 넣지 않고 "새 메시지가 있습니다"와 링크만 넣는다.

### F6. 안전

- **차단:**
  - 대화 상대를 차단하면 양쪽 모두 그 방에 새 메시지를 보낼 수 없다. 기존 메시지는 볼 수 있다.
  - 차단은 차단한 사람만 풀 수 있다.
- **신고:**
  - 프로필이나 메시지를 사유 코드와 설명(최대 500자)으로 신고한다.
  - 기록하는 것: 신고 ID, 신고자, 대상, 사유, 시각, 처리 상태, 신고된 메시지의 사본.
  - 같은 사람이 같은 대상을 중복 신고하면 기존 신고를 돌려준다.
  - 신고자에게는 "접수되었습니다"만 보여준다.
- **운영:**
  - MVP에는 관리자 화면이 없다.
  - 운영자 계정만 신고 기록을 조회할 수 있고, 조회 기록을 남긴다. 운영자도 신고되지 않은 대화는 볼 수 없다.
  - 허위 신고번호나 허위 프로필이 확인되면 운영자가 프로필을 숨긴다.

### F7. 개인정보·탈퇴

- 개인정보 처리방침 페이지를 둔다. 가입 화면에서 링크한다. 공개 출시 전에 완성한다.
- 탈퇴는 F1과 함께 만든다. 뒤 기능은 각자 자기 데이터의 탈퇴 처리를 인수 테스트에 넣는다.
  - 프로필, 대학 이메일, 찜은 즉시 삭제한다.
  - 탈퇴자가 보낸 메시지는 본문을 지우고 "탈퇴한 사용자"로 표시한다.
  - 신고된 메시지 사본은 신고 처리가 끝날 때까지 보관한다.
  - 같은 이메일로 다시 가입해도 복원하지 않는다.
- **보관 기간 (2026-10-15 사용자 확정):**
  - 마지막 메시지 후 1년이 지난 대화는 삭제한다.
  - 처리가 끝난 신고 기록은 90일 뒤 파기한다.
  - 인증 코드는 만료 즉시 삭제한다.

### F8. 찜하기

- 학부모만 쓴다. 공개 프로필을 찜하고, 해제하고, 목록으로 본다.
- 숨기거나 삭제된 프로필은 찜 목록에서 빠진다.

## 구현 순서

조각마다 인수 테스트 원본을 먼저 쓰고 구현한다 (`AGENTS.md` ①~⑤).

| 순서 | 조각 | 메모 |
|---|---|---|
| 1 | F2 프로필 + F4 검색 | 로그인 전이지만 테스트에서 주입한 선생님 주체로 쓰기 API를 호출한다. 401·403은 처음부터 고정한다. API 경계는 T-043 표를 따른다 |
| 2 | F1a 이메일 코드 로그인 + 탈퇴 | 이메일 발송 기능도 여기서 만든다. 1의 원본 기대값은 바꾸지 않는다 |
| 3 | F3 대학 이메일 확인 | 2의 발송 기능을 다시 쓴다 |
| 4 | F5 채팅 + 이메일 알림 + F6 차단·신고 | F7 보관 기간을 따른다 |
| 5 | F8 찜하기 | |
| 6 | F1b 카카오 로그인 | 카카오 개발자 앱 등록은 사용자가 한다 |

- 프론트엔드(`frontend/`, Vite + React + TS)는 API가 생기는 순서대로 agy가 붙인다.
- E2E는 Playwright로 한다. 하네스(verify full·CI)에 붙이는 방법은 프론트엔드 첫 조각에서 정한다.

## 공개 출시 전 확인 목록

1. **대구동부교육지원청:**
   - 프로필의 광고 표시 방식이 맞는지
   - 면제자의 신고번호 칸 처리
   - 교습비 표시 기준
2. **통신판매중개 해당 여부:** 실제 문의·채팅 흐름 기준으로 판단한다. 해당하면 비당사자 고지와 분쟁 처리를 넣는다 (regulation §3).
3. 개인정보 처리방침 문안.
