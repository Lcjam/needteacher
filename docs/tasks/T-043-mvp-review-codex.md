### 총평과 우선순위

방향은 전단지 대체에 맞다. 다만 현재 문구 그대로는 공개 광고 표시, 인증·수정 권한, 채팅·신고 데이터의 처리 기준을 인수 테스트로 고정할 수 없다. 아래 P0은 첫 원본 작성 또는 공개 출시 전에 명세를 확정해야 하는 항목이다. 법령 판단은 T-042의 조사 범위에 따르며, `미확인`으로 표시된 사안은 확정된 의무로 단정하지 않는다.

### 구현 순서 1의 API 경계 제안

첫 원본은 F2+F4의 **HTTP 계약**을 고정한다. `POST/PATCH`는 테스트 설정에서 선생님 주체를 주입하여 호출한다. 실제 로그인 구현 전에도 미인증·타인 주체의 쓰기는 거부한다. 목록/상세 읽기는 공개 프로필만 허용한다. 아래 필드명·상태값은 제안이므로 원본 테스트를 작성하기 **전에** 명세에서 확정한다.

| 엔드포인트 | 요청 | 성공 응답 | 오류·경계 |
|---|---|---|---|
| `POST /api/v1/tutor-profiles` | 주체=선생님. 본문 `displayName`, `subjectCodes[]`, `gradeCodes[]`, `dongCodes[]`, `tuition{amountWon,unit,sessionMinutes,sessionsPerMonth}`, `declarationType=REPORTED/ENROLLED_EXEMPT`, `registrationNumber`(REPORTED만), `university`, `department`, `highSchool?`, `introduction?` | `201`, `Location`, `id`, `ownerId`, `visibility=HIDDEN`, `createdAt`, `updatedAt`, 입력의 정규화 값. 초안은 비공개로 생성. | 미인증 `401`, 학부모 `403`, 이미 자기 프로필 있음 `409`, 필수·코드·가격·신고 유형 불일치 `400`. `ownerId`는 본문에서 받지 않는다. |
| `PATCH /api/v1/tutor-profiles/{id}` | 주체=작성자. 변경 필드만 전달; `null` 삭제 허용 필드는 선택 항목에 한정. 공개 중에도 가격/신고 필수값을 지켜야 함. | `200`, 갱신된 전체 프로필·`updatedAt`. | 미인증 `401`, 타인 `403`, 없음 `404`, 잘못된 값 `400`; 변경 없으면 `updatedAt` 유지. |
| `PATCH /api/v1/tutor-profiles/{id}/visibility` | 주체=작성자, `{visibility:"PUBLIC"|"HIDDEN"}` | `200`, `id`, `visibility`, `updatedAt` | `401/403/404`; 공개 필수값 누락 `400`. 숨긴 뒤 목록·공개 상세에 즉시 비노출. |
| `GET /api/v1/tutor-profiles` | `dongCodes?`, `subjectCodes?`, `gradeCodes?`(쉼표 구분), `limit?`, `cursor?`; 동일 필터 OR/필터 간 AND. | `200`, `items[]`(id, 표시 이름, 과목, 학년, 동, 교습비와 기준, 신고 유형/신고번호 해당 시, 이메일 확인 여부, 고교), `nextCursor`; `updatedAt DESC,id DESC`. | 잘못된 코드·limit·cursor `400`; 결과 없으면 빈 배열. 숨김 프로필 제외. |
| `GET /api/v1/tutor-profiles/{id}` | 경로 ID | `200`, 공개 프로필 전체 표시 항목. 연락처·인증 이메일·내부 작성자 식별자는 미노출. | 없음·숨김 `404`(존재 여부 누출 방지). |

공통 오류 본문은 `{code,message,fieldErrors?}`로 고정한다. 가격은 `PER_SESSION`이면 `sessionMinutes`, `PER_MONTH`이면 `sessionMinutes`와 `sessionsPerMonth`를 필수로 하는 식으로 기준을 고정한다. 코드 목록은 첫 원본에 쓰는 실제 수성구 동·과목·학년 값과 함께 버전/출처를 확정한다. 공개 목록의 신고번호 표시 방식은 관할기관 확인 결과로 최종 확정해야 한다. 원본 테스트는 `src/test/java`에 **새 파일**로 작성하고 red/형식 확인 뒤 하네스 절차에 따라 오케스트레이터가 이동한다. 이후 권한 공급 방식이 바뀌어도 원본의 HTTP 기대값은 유지한다.
